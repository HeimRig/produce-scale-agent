# 长稳测试

- 连续 40 单，间隔 1.0s，TTS 后端 EdgeTTS，收尾观察 25s
- 模型 produce_mobilenetv3s.onnx，闭环保留语音异步不阻塞

## 结果

| 指标 | 数值 |
|---|---|
| 单均价 | 107.4 ms |
| P50 / P95 / 最大 | 107.2 / 118.8 / 131.3 ms |
| 首 10 单均值 → 末 10 单均值 | 111.3 → 106.1 ms |
| 总墙钟（不含收尾） | 44.3 s |
| 线程峰值 | 10 |
| 播报队列峰值 | 3 |
| 因超过并发上限丢弃 | 28 次 |
| 临时 mp3 残留 | 0 → 0 |
| 进程 RSS 变化 | +9.4 MB |

## 判读

- 末 10 单均值不应高于首 10 单，否则说明有资源没释放。
- 临时文件应收敛回起始值，播报线程应回到 0，否则是清理逻辑漏了。
- 线程峰值应持平而不是逐单抬高。
- RSS 在头十几单会有一次跳升（加载 edge-tts / TLS 模块），之后基本持平；只看绝对值判断不了泄漏。
- 间隔小于语音时长（合成 1.4s + 播放约 5s）时会出现主动丢弃，这是设计行为：宁可少播一句，也不让播放器排队积压几十个进程。
- 语音异步不阻塞，所以单均延迟反映的是识别+称重+计价+打票四步。

## 两轮对比

| | 12 单 / 间隔 2s | 40 单 / 间隔 1s |
|---|---|---|
| 单均价 | 105.5 ms | 107.4 ms |
| 首 10 → 末 10 | 105.0 → 104.9 | 111.3 → 106.1 |
| 临时 mp3 | 0 → 0 | 0 → 0 |
| 线程峰值 | 10 | 10 |
| RSS | +7.8 MB | +9.4 MB |

RSS 从 12 单到 40 单只多涨 1.6 MB，是模块加载与 GC 抖动，不是线性泄漏；延迟在两轮里都没有随单数上升。

**判定：通过**
